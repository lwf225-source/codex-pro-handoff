# 使用说明

## 前提与聊天选择

安装并让宿主发现技能后，用户选择并确认一个普通 ChatGPT Pro Chat。不同项目使用各自合适的聊天，没有预设账号、项目路径或聊天 ID。若已有确认仍有效，可复用，无须每轮重新确认；模型、聊天身份或项目发生变化时再核对。

直接路径需要宿主的 `list_threads`、`send_message_to_thread`、`read_thread` 支持普通 ChatGPT Chat。先检查工具是否存在及其实际参数，不把这些名称当作可供任意客户端调用的公开 API。发送时不覆盖 `model` 或 `thinking`，不要把消息投递到 Work 或 Codex 聊天。

直接路径不可用时，使用宿主支持的内置浏览器；复用页面或打开 ChatGPT 首页一次，确认登录、普通 Chat 和用户选择的 Pro 模型。如果需要登录，由用户完成。后续复用这一确认；思考期间不反复打开或刷新 Browser。如果宿主没有可用路径，就报告缺失能力，不能用 Codex 自查冒充 Pro 回复。

## 材料与阶段

先确定用户要求：仅规划、仅验收，还是授权实施的完整流程。仅验收现有成果时直接提交证据，跳过规划与实施。仅规划时取得真实方案后停止。完整流程由 Pro 提供方案、Codex 在授权范围内执行，再把实际证据交回同一聊天。

分享前检查材料。选定源码、diff、测试输出和实际运行证据能支持代码审查；项目摘要只能提供背景。去掉凭据、个人信息和无关私人记录。对于不能安全分享的证据，明确相应验收项为 unknown，不补造材料。

文件上传能力依赖宿主版本和账号。按实际能力选择可审阅的小段文本、获准的连接来源或由用户上传，不把历史上传限制写成当前产品保证。可选 Linker 只整理背景，需刷新并审阅输出；本包不会安装它或配置同步。

## 新轮次与等待

发送前后记录足够的轮次证据，例如消息 ID、时间戳或请求标记。读取时确认聊天一致、回复属于刚发送的请求且已完成。旧缓存、已有历史回复、发送成功都不等于当前任务完成。

使用宿主支持的等待或读取机制，间隔读取，不能因回复缓慢重发。Codex 专用的等待工具不能默认用于普通 Chat。不需要反复 Browser 循环。宿主若不能持续等待，保留待完成轮次并说明缺哪一步；后台续接需要宿主能力及相应用户授权，本包没有后台执行器。

## 验收报告

请 Pro 按标准给出 pass / revise / unknown，并指出所见证据和缺失检查。Codex 需独立核实可验证的意见；只有具体范围内失败才触发修订和下一轮。最终说明 Pro 看过什么、Codex 实测什么，以及设备、部署、生产或用户验收仍缺什么。

已知历史观察来自 2026 年 9 月 20/21 日；它们没有证明当前模型、配额或上传限制，也没有证明完整无人值守闭环。此包本地测试不调用 Pro，不能提升这些证据等级。模型名称和政策变化时需另行核实，不承诺节省百分比。
